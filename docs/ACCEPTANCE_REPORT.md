# รายงานตรวจรับ OneVentOne

ทดสอบวันที่ 10 พฤศจิกายน 2569 ตามเกณฑ์ Prompt 4 และ [ข้อกำหนดโครงการ](PROJECT_CONTRACT.md) บน Windows, Node.js 24.11.0, Next.js 16.4.6, Prisma 6.19.3 และ MongoDB 8.0.17 replica set ใช้ฐานข้อมูล QA ชั่วคราว บัญชีทดสอบ และภาพจำลองแยกจากข้อมูลพัฒนา เว็บทดสอบฟังเฉพาะ localhost

## ผลการตรวจ

| เกณฑ์ | วิธีตรวจและผล |
| --- | --- |
| Prisma และ build | `db:validate`, `npm run typecheck`, `npm run lint` และ `npm run build` ผ่าน โดย build รัน `prisma generate` ด้วย |
| Schema, indexes และ seed | `db push` บน DB ว่างสร้างครบ 26 collections และ 49 indexes ตาม schema โดยไม่นับ `_id` รัน seed สองรอบแล้วยังคงมีอีเวนต์ 1 งาน หน่วยขาย 20 หน่วย และบัตรยืน 2 ราคา |
| HTTP Auth | เปิด `RUN_HTTP_TESTS=1` แล้วทดสอบสมัครด้วย role ที่ส่งมาจาก client ผลใน DB เป็น `CUSTOMER` เท่านั้น ตรวจการเข้ารหัสรหัสผ่าน การอ่าน session พร้อมกัน 8 คำขอ การให้และถอนสิทธิ์จาก session เดิม การปฏิเสธคำขอแก้ไขจาก origin อื่น และการออกจากระบบ |
| แบรนด์และช่องทางโอน | เบราว์เซอร์เห็นชื่อ OneVentOne และอ่านชื่อร้าน โลโก้ทดสอบ และบัญชีโอนตัวอย่างจาก `BusinessProfile` |
| การจองผ่านเบราว์เซอร์ | Edge headless ที่ 360, 768 และ 1440 px ทดสอบโต๊ะ 1 โต๊ะ ที่นั่ง 1 ที่ และบัตรยืน 2 ใบตามลำดับ หน้าจองไม่ล้นแนวนอน เมื่อ reload ยังใช้เวลาหมดสิทธิ์เดิม ส่งสลิปแล้วอยู่ในคิวตรวจและไม่มี QR แอดมินอนุมัติแล้วออก QR 4, 1 และ 2 ใบตามลำดับ |
| การเข้าถึงและสถานะเครือข่าย | ใช้ Tab ไปยังลิงก์ข้ามไปยังเนื้อหา ใช้ Enter เลือกวัตถุจากรายการผัง ทดสอบ loading และปิดแอนิเมชัน spinner เมื่อเปิด reduced motion จำลองคำขออ่านที่ว่างล้มเหลวแล้วกดลองอีกครั้งสำเร็จ ไม่พบข้อผิดพลาด JavaScript ที่หลุดขึ้นมาระหว่าง flow |
| การจองพร้อมกัน | 20 คำขอแย่งหน่วยสุดท้ายได้หนึ่งรายการ รายการหลายหน่วยที่ไม่สำเร็จ rollback ทั้งหมด และบัตรยืนหลายราคาใช้โควตาร่วมโดยไม่ขายเกิน |
| คำขอซ้ำ | การส่ง key เดิมยืนยันผลเดิมของการจอง ส่งหลักฐาน อนุมัติ และคืนเงิน ตรวจแล้วว่ามีหลักฐานชำระเพียงหนึ่งรายการต่อการส่งซ้ำและไม่ออก QR เพิ่ม |
| อายุการจองและการแข่งขันระหว่างคำขอ | หมดอายุแล้วคืนสิทธิ์ unpaid เท่านั้น การส่งหลักฐานที่แข่งกับการหมดอายุไม่คืนชีพการจอง และอนุมัติกับปฏิเสธพร้อมกันสำเร็จได้ทางเดียว |
| สิทธิ์และข้อมูลส่วนตัว | ชุดทดสอบธุรกรรมยืนยันว่าบัญชีอื่นและเจ้าหน้าที่ที่ถูกถอนสิทธิ์เปิดสลิปไม่ได้ ตรวจ HTTP แล้วว่าเจ้าของเปิดไฟล์ได้พร้อม `Cache-Control: private, no-store` และผู้ที่ไม่เข้าสู่ระบบได้ 401 |
| ออกบัตรและเช็กอิน | ตรวจรหัสเดียวกันสองครั้งจากหน้าหลังบ้าน รอบแรกนับเข้างานหนึ่งคน รอบสองขึ้นว่าใช้แล้ว ชุดทดสอบธุรกรรมยังยืนยันการตรวจพร้อมกันและการปฏิเสธบัตรที่ถูกเพิกถอน |
| ยกเลิก คืนเงิน และรายงาน | ทดสอบผ่าน API ว่าการยกเลิกสร้างยอดรอคืนก่อนบันทึกหลักฐานคืนเงิน ยอดรับ 3,970 บาท ยอดคืน 790 บาท และยอดสุทธิ 3,180 บาทหลังส่งคำขอคืนซ้ำ จำนวนผู้เช็กอินเป็น 1 และสิทธิ์ขายลดจาก 7 เป็น 6 เมื่อยกเลิกที่นั่ง |
| การเผยแพร่ผัง | เพิ่มวัตถุใน editor บันทึก เปิดใหม่ ตรวจ ID และพิกัด เปิดพรีวิว แล้วเผยแพร่เป็นเวอร์ชันใหม่ การจองทั้งสามยังอ้างผังเดิม ชุดทดสอบ catalog ตรวจเพิ่มเรื่องการชนกันของร่าง ความครบของหน่วยขาย และราคาเดิม |

ชุดทดสอบ Node ที่รวม HTTP Auth และธุรกรรมจริงบน MongoDB ผ่าน **17 รายการ** ไม่มีรายการตกหรือถูกข้าม

## ปัญหาที่พบและการแก้ไข

- Windows ตอบ `EPERM` ตอน `prisma generate` เพราะ dev server ของโปรเจกต์เปิด Prisma DLL อยู่ หลังหยุดโปรเซสดังกล่าว คำสั่ง build แบบเต็มผ่าน
- HTTP Auth และเบราว์เซอร์ที่เรียกพร้อมกันพบ MongoDB write conflict (`P2034`) ในตัวนับ rate limit ของ Better Auth เพิ่มการ retry แบบจำกัดรอบที่การเพิ่มตัวนับ และเพิ่มกรณีตรวจ session พร้อมกัน 8 คำขอใน [HTTP auth test](../tests/auth.integration.test.ts)
- ผังในหน้าจองที่ 360 px ดันความกว้างของทั้งหน้า ปรับความกว้างขั้นต่ำของคอลัมน์ที่ breakpoint มือถือให้ย่อได้ แล้วทดสอบว่าเลื่อนผังภายในกรอบและจองต่อได้ที่ทั้งสามขนาดจอ
- Build ยังเตือนเรื่อง Turbopack tracing เมื่ออ่าน path ของสลิปจาก runtime และเรื่อง Prisma 6 จะเลิกใช้ค่า seed ใน `package.json` เมื่อเปลี่ยนไป Prisma 7 ทั้งสองรายการเป็นคำเตือนและ build จบด้วย exit code 0

## ทดลองระบบจาก seed

1. ทำตาม [การเริ่มระบบบน Windows](../README.md#เริ่มในเครื่อง-windows) ถ้ามี DB และ seed แล้ว ให้เปิด `npm.cmd run db:dev` ค้างไว้ แล้วรัน `npm.cmd run dev` ในอีกหน้าต่าง
2. สร้างผู้ดูแลทดสอบตาม [ขั้นตอน bootstrap](../README.md#สร้างผู้ดูแลครั้งแรก) และสมัครบัญชีลูกค้าอีกหนึ่งบัญชี
3. เปิด `http://127.0.0.1:3000` เลือก MONGKOL LIVE SESSION จองโต๊ะ ที่นั่ง หรือบัตรยืน แล้วส่งไฟล์ภาพจำลองจากหน้า checkout บัญชีใน seed เป็นบัญชีตัวอย่างสำหรับสาธิต
4. เข้า `/admin/bookings` ด้วยบัญชีผู้ดูแล เลือกหลักฐาน กรอกยอดสมมติเต็มจำนวนและเหตุผล จากนั้นอนุมัติ แล้วกลับบัญชีลูกค้าเพื่อดู QR
5. ที่ `/admin/check-in` เลือกอีเวนต์และกรอกรหัสใต้ QR ตรวจรหัสเดิมอีกครั้งเพื่อดูข้อความว่าบัตรถูกใช้แล้ว สำหรับการทดสอบผัง ให้บันทึกร่าง เปิดหน้าใหม่ แล้วเผยแพร่เวอร์ชันใหม่จากหน้าผังของอีเวนต์

## ขอบเขต MVP และงานหลังส่งมอบ

- ตรวจรับบนเครื่องพัฒนา ยังไม่ได้ทดสอบกล้องจริงหรืออุปกรณ์มือถือจริง และยังไม่ได้ตรวจสภาพแวดล้อม production, Atlas, Docker หรือ reverse proxy
- รุ่นนี้บันทึกผลตรวจโอนและผลคืนเงินที่เจ้าหน้าที่ดำเนินการภายนอก ใช้ private local storage และยังไม่มีบริการรีเซ็ตรหัสผ่านทางอีเมล
- งานหลังส่งมอบแยกจากเกณฑ์ MVP ได้แก่ ตั้งค่า production และ HTTPS, private persistent storage กับการสำรองข้อมูล, scheduler ของงานหมดอายุ, trusted proxy สำหรับ IP ของ rate limit และ mail service หากต้องการเปิดรีเซ็ตรหัสผ่าน
